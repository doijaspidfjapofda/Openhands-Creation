# 纸间 PDF · 本机 PDF 工具

一款在本机运行的 PDF 工具：打开、预览、合并、拆分、页面整理和格式转换都在当前电脑完成。
应用没有上传入口，不调用云端处理接口，不含账号、遥测或隐藏联网功能。

- 桌面版：双击 `纸间PDF.exe`（Windows 便携版，见下文“Windows 使用方式”）。
- 开发版：`node server.js`，用浏览器打开 `http://127.0.0.1:5173/index.html`。
- 待办与已知缺陷：见仓库根目录 [`PRD-改进与缺陷清单.md`](../../PRD-改进与缺陷清单.md)，后续改动按该文档逐条实施。

## 已实现并通过验证

| 功能 | 说明 | 验证方式 |
| --- | --- | --- |
| 打开与预览 | 本机文件选择或拖放，PDF.js 渲染页面与缩略图，缩放、翻页、选页；读取时显示 `已读页数 / 总页数`，按 Esc 可取消 | 浏览器端到端测试：核对进度文字与大文档打开 |
| 合并 PDF | 选择多个 PDF，拖动或上移/下移调整顺序，可选在文件之间插入空白分隔页 | 单元测试 + 端到端测试：重新打开输出，核对页数与页面文字顺序 |
| 拆分与提取 | 按页码范围（`1-3, 5`）、每 N 页、当前选中页拆分；结果打包为 ZIP | 单元测试 + 端到端测试：核对每个输出文件的页数与内容 |
| 页面整理 | 拖动排序（鼠标与触屏/手写笔均可），或用“上移 / 下移 / 移到第 N 页”与 `Alt+↑`/`Alt+↓` 排序；左/右旋转、复制、删除、插入空白页（尺寸可跟随相邻页 / 当前页 / A4 / Letter），撤销/重做。缩略图按可视区域渲染，页数不受 80 页限制 | 单元测试 + 端到端测试：120 页文档把第 100 页移到首位、触屏指针拖动、空白页尺寸，核对导出页序与页面尺寸 |
| 最近文件 | 记录保存在本机（浏览器本地存储 / 桌面版用户数据目录），只含文件名、页数、大小、时间；桌面版另存路径，可从列表重新打开。设置里可关闭或清除 | 端到端测试（刷新后仍在、不含内容）+ 桌面测试（按路径重新打开） |
| 另存新文件 | 默认另存，原文件只读不写；浏览器不支持系统保存窗口时回退为下载 | 端到端测试：检查下载文件名与内容 |
| PDF → 图片 | PNG/JPEG，150/200/300 DPI，全部页/当前页/自定义范围，输出 ZIP | 单元测试 + 端到端测试：检查 PNG 文件头与像素尺寸 |
| 图片 → PDF | PNG/JPEG 按列表顺序每页一张，页面方向可选自动/纵向/横向 | 单元测试 + 端到端测试 |
| PDF → 文本 | 提取 PDF 文字层，按页输出为 `.txt`；按坐标重排，双栏排版逐栏输出 | 单元测试（双栏/单栏顺序）+ 端到端测试 |

错误处理：加密 PDF、损坏文件、空文件、页码越界、页码范围重叠、每份页数为 0 或小数、图片格式不支持、
内存不足、用户取消，都有对应提示；未接入的功能不会生成文件。

未保存保护：页面调整或合并顺序改动后，桌面版关闭窗口会询问“去保存 / 放弃改动并关闭 / 取消”，
浏览器版使用系统离开确认；打开新文件或保存成功后自动清除该状态。

## 尚未接入（界面会明确标注，不会生成假结果）

| 功能 | 未接入原因 |
| --- | --- |
| 压缩 PDF | 浏览器内没有可靠的、保留文字层的压缩器。把每页重新编码为图片虽能减小体积，但会破坏文字可选中、可搜索，不能当作“压缩”交付。 |
| 编辑 PDF 原有文字 | 需要重建字体与排版，当前没有可靠的本地引擎；界面只支持叠加对象预览。 |
| 批注、手写/图片签名 | 对象模型尚未与页面导出打通；证书数字签名需要读取本机证书，未接入。 |
| 表单填写 | 尚未实现字段枚举与写入；没有可验证的表单引擎。 |
| 对比两个 PDF | 只有界面演示，没有真实差异算法。 |
| 密码保护 / 移除密码 | pdf-lib 不支持加密写入；也不会提供任何破解入口。 |
| 脱敏 | 只在页面上盖住文字不算安全脱敏。当前无法从 PDF 内容中真正移除并验证不可恢复，因此不提供。 |
| OCR、Office/网页转 PDF、PDF 转 Word/PPT/HTML | 需要额外的本机识别或排版引擎，当前版本未包含；不会改用云端。 |

页面编辑面板中的“添加到页面”、批注面板中的标记、对比差异、保护与脱敏等交互仍属界面预览，
执行时会显示“尚未接入”，不会写出文件。

## 导出时会丢失的文档级内容

合并、拆分和页面整理通过复制页面内容生成新文件，以下内容可能不会保留：

- 书签/大纲、页面标签
- 交互式表单字段（AcroForm）与其值
- 数字签名与签名校验信息
- 文档级元数据（标题、作者、关键词等）
- 页面间链接、附件、部分注释
- 结构化标签（无障碍信息）

页面的 `CropBox`（裁剪区域）与旋转角会随页面一起复制，导出后可见区域与原文件一致（已由测试覆盖）。

PDF → 图片、PDF → 文本是有损转换：图片不再有文字层，文本不再有版式。

## 保存行为

- 合并、页面整理、图片转 PDF 输出 `.pdf`；拆分与 PDF 转图片输出 `.zip`；PDF 转文本输出 `.txt`。
- 桌面版点击保存会弹出 Windows 的“另存为”窗口，由你选择文件名和位置（`desktop/preload.js` 只暴露
  这一个能力，页面拿不到 Node API）。
- 浏览器模式：支持系统保存窗口时由你选择位置，否则下载到浏览器默认下载目录。
- 取消保存不会写入任何文件，也不会修改原文件。
- 顶栏“保存副本”只复制原文件，不做任何改写。
- 页面设置了严格的内容安全策略（`script-src 'self'`，禁止 eval 与外部脚本），Electron 也禁止外部导航。

## Windows 使用方式

### 方案比较（实施前评估）

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| Electron（已采用） | 复用现有页面与本地依赖；原生窗口、应用图标；可打包为便携版或安装包 | 体积约 110 MB（含 Chromium） |
| Tauri | 体积小，使用系统 WebView2 | 需要 Rust 工具链；目标机需 WebView2 运行时；现有页面需改动构建方式 |
| 自带 Node + 浏览器启动器 | 改动最小 | 打开的是浏览器标签页，不像桌面应用 |
| Node 单文件可执行 | 单一 exe | 仍会打开浏览器；构建方式较绕 |

### 便携版

```
dist/纸间PDF-win32-x64/纸间PDF.exe      ← 双击启动
dist/纸间PDF-windows-x64.zip            ← 整个目录的压缩包
```

- 解压后双击 `纸间PDF.exe` 即可，不需要安装 Node.js，也不需要打开命令行；要求 64 位 Windows 10 或更高版本。
- 首次启动 Windows SmartScreen 可能提示“未知发布者”，因为该产物未做代码签名（选择“更多信息 → 仍要运行”）。
- 发布包内是完整的 Electron 33.2.1 运行时，与官方 win32-x64 发行版逐文件比对只少了被替换的
  `resources/default_app.asar`，因此目标机不需要任何开发环境。
- 应用启动时只在 `127.0.0.1` 上开启本地静态服务供窗口加载界面，不对外网开放。

重新生成 Windows 产物：

```powershell
npm install
npm run package:win
```

（打包脚本用 `@electron/packager` 交叉生成 Windows x64 目录并压缩为 ZIP，不会上传任何内容。）

### 开发模式

```powershell
node server.js
```

或双击 `启动预览.bat`。直接双击 `index.html` 可能被浏览器限制 PDF Worker。

## 测试

```powershell
npm install          # 仅安装开发测试依赖（pdfjs-dist、playwright、electron 等）
npm test             # 逻辑与隐私检查（合并、拆分、页面整理、转换、桌面外壳）
npm run test:e2e     # 另加真实浏览器端到端测试
npm run test:desktop # 在真实 Electron 窗口里跑完整流程（无显示器环境用 xvfb-run -a）
```

当前共 92 项检查：逻辑/静态 69 项、Chromium 端到端 14 项、Electron 桌面窗口 9 项。

```powershell
# 用打包后的 app.asar 再跑一遍桌面流程，确认发布包本身可用
ZJ_APP_TARGET=$PWD/dist/纸间PDF-win32-x64/resources/app.asar npm run test:desktop
```

- 测试用的 PDF 与图片都由测试代码即时生成，不含任何真实或私人文件。
- 端到端测试会启动本机服务、用 Chromium 打开界面、真实执行操作，并重新解析保存下来的文件；
  同时阻断所有非本机网络请求，验证断网可用。
- 测试覆盖：合并页数与顺序、空白分隔页、拆分三种模式与非法输入、旋转/复制/删除/空白页/拖动排序/
  撤销重做、原文件不变、加密与损坏文件、取消处理、转换三种方向、未接入功能不产生文件。
- 桌面测试在真实 Electron 窗口里验证：启动与窗口隔离、阅读（页数/翻页/跳页/缩放）、页面管理、
  另存为、三种转换、未接入工具不落盘、无外部请求与脚本错误。
- 未能在此环境验证的部分：Windows 二进制本身只做了静态检查（PE x64 / GUI 子系统 / 内嵌图标 /
  与官方运行时逐文件比对）和“用 Linux Electron 加载同一份 app.asar”的运行验证；Wine 10 无法启动
  Electron 33，不能代替 Windows 实测。首次在 Windows 10 上运行时请确认窗口能打开且“另存为”对话框正常。

## 隐私

- 应用只使用浏览器文件选择器读取你主动选择的文件，不获取完整磁盘路径。
- 文件数据只在当前标签页内存中处理，关闭页面后释放。
- 所有脚本、字体渲染组件与处理库均从 `vendor/` 与 `assets/` 本地加载，运行时不请求 CDN。
- 本地服务只绑定 `127.0.0.1`，并校验请求路径位于应用目录内。
- 桌面版禁止导航到外部地址，外部链接交给系统浏览器打开。
